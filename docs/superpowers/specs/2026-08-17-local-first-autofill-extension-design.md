# 本地优先求职自动填写扩展设计

## 目标

将现有的“求职工作台预填助手”升级为独立、可在任意招聘网站使用的 Manifest V3 浏览器扩展。它提供多份简历资料、本地字段答案、页面字段识别、可选 AI 映射、填写审计和提交前复核。扩展不提供订阅、支付、账号或云端同步；用户自行配置模型 API。

本设计实现公开产品页面所展示的核心工作流，但不复用其品牌、代码、文案、图像或用户评价。产品名称保持“求职工作台”。

## 产品边界

- 资料、简历模板和 API 配置保存在 `chrome.storage.local`。不建立后端，不上传至本项目服务。
- API Key 仅在扩展本地保存。只有用户点击“使用 AI 识别”时，扩展才向用户配置的 API 发起请求。
- 确定性规则优先填写姓名、邮箱、电话、教育、学校、专业、城市、链接、工作授权和自定义答案。AI 只处理规则未识别的字段映射。
- 文件上传、登录、验证码、OTP、敏感声明题、未知必填题和最终提交不自动执行。扩展将这些项目列入待人工处理清单。
- 站点访问采用 `optional_host_permissions` 按域名请求；不在固定 `host_permissions` 中加入 `<all_urls>`。
- “零收费”仅指本扩展无订阅与平台收费。用户自己的模型 API 以及 Chrome 商店开发者注册可能由相应服务方收费。

## 模块

### 资料库与设置

`extension/profile-store.js` 定义一个版本化的本地数据模型：`profiles`、`activeProfileId`、`provider` 与 `customAnswers`。每份资料带有名称、基础联系方式、教育、位置、网址、常用问答和简历文件名。侧栏支持新增、复制、删除、切换和编辑资料。

`extension/api-client.js` 支持 OpenAI 兼容 `chat/completions` 与自定义 JSON POST。配置包含 URL、模型、API Key、请求头、请求模板和响应路径。保存配置前会请求 API 域名访问权限；无配置时，扩展仍可使用规则填写。

### 页面识别与映射

`extension/form-analysis.js` 将可见 `input`、`textarea`、`select`、可编辑节点和单选/复选题转为稳定的字段快照。快照仅包含标签、名称、ID、placeholder、autocomplete、可选项、required 与 type；不会抓取整个页面内容。

本地分类器使用 `autocomplete`、标签、`name`、`id`、`placeholder` 和输入类型给出 canonical field key 与置信度。`extension/field-mapping.js` 将 canonical key 映射到当前资料，匹配自定义答案，并生成 `ready`、`manual`、`sensitive`、`unsupported` 四类审计结果。

用户点击“使用 AI 识别未知字段”后，侧栏将字段快照和当前资料允许填写的值发送到用户 API，要求返回严格 JSON 映射。返回内容经过 URL、字段 ID 和答案白名单验证，不能调用页面代码或生成提交动作。

### 侧栏流程

侧栏固定为五个区域：当前资料、当前页面支持度、待填写字段、审计/复核和 API 设置。用户先选择资料，点击“分析页面”，再点击“填写已审核字段”。每个结果显示页面标签、候选值、状态与原因；填写后仍可逐项复核。侧栏不包含“自动提交”按钮。

现有本地工作台桥接保留，批量预填会使用新的通用注入逻辑。华为、腾讯和 PwC 的职位采集仍可用，但不再限制普通表单识别到这三家网站。

### 权限与商店准备

扩展使用 MV3、`storage`、`sidePanel`、`tabs`、`scripting` 和动态域名访问权限。商店材料位于 `store/`：隐私政策、商店描述、权限说明、测试步骤与 ZIP 打包脚本。发布包不含 API Key、测试资料或本地工作台数据。

## 验证

- 单元测试验证：资料库迁移、表单字段快照、规则分类、敏感字段阻止、AI 映射规范化、实际写入事件、动态权限清单和 manifest。
- 通过 `npm test`、`npm run lint`、`npm run build` 与扩展脚本语法检查。
- 浏览器 QA：测试标准招聘表单中的分析、填写、未知题、文件上传和人工复核；桌面侧栏与 390px 宽度均无溢出。
- 使用 Chrome 的“加载已解压的扩展程序”验证。商店发布前生成无私密数据的 ZIP、截图和商店说明。
